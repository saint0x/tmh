# 1. Introduction

The key-value cache is unusual among the large objects in an inference server. Model weights are loaded once and then reused. Activations are temporary. KV state grows while requests are running, remains addressable for the rest of each sequence, and is often shared when prompts have a common prefix. At long context or high concurrency, its size determines how much work the server can admit.

PagedAttention made this state tractable by replacing contiguous request buffers with fixed-size logical blocks [@kwon2023pagedattention]. Paging reduced fragmentation and made prefix sharing practical, but it left one assumption largely intact: every block in a cache has the same physical representation. The allocator sees a block at the start of a prompt, a block being written by the current decode step, and a block that has been read for thousands of steps as interchangeable pieces of storage.

They are not interchangeable in use. The first page is long-lived and commonly shared. The newest page is mutable, latency-sensitive, and read immediately after it is written. Most older pages are stable; during ordinary decoding they are read but no longer changed. A uniform BF16 cache pays the highest storage cost for all three cases. Uniform quantization lowers the cost, but also brings conversion and dequantization into the hottest region of the request. Eviction saves more memory by discarding old state, yet it fails when an answer depends on evidence outside the recent window.

TMH starts from these runtime roles. It keeps an anchor page and a recent tail in the model's native cache type. Older keys use INT8. Older values use packed INT4 in the first two thirds of the network and INT8 in the final third. The fixed layer split is intentionally modest: it is not claimed to be an optimal sensitivity schedule. Its purpose is to expose the systems work created by heterogeneous pages—allocation, naming, sharing, metadata, conversion, and execution—without placing an online importance model in the serving loop.

The implementation retains the logical block number used by the scheduler and adds a physical role and slot beneath it. A page-aligned descriptor tells cache update and attention which pool owns a block and how its bytes should be interpreted. If page roles are known before prefill, new tokens can be written directly into raw or compressed storage. The resulting request may contain both representations, so attention reconstructs warm keys and values as it traverses the logical sequence.

That direct-placement path is the part evaluated in this paper. A full hierarchy needs another operation: a populated raw page must be converted before its descriptor changes to a warm slot. Prefix reuse creates a related case in which one request wants a raw view of a canonical warm page. The prototype allocates destinations for those paths but does not fill them with the existing KV payload. Calling that state a completed dynamic hierarchy would obscure the main engineering fact. TMH presently demonstrates static heterogeneous placement inside a production server; migration remains part of the design, not part of the working data path.

The distinction changes how the evidence should be read. Capacity follows from tensor shapes and can be measured without a fast kernel. For the evaluated 48-layer profile, the physical pool admits 73.82% more logical KV blocks than an all-BF16 layout at the same budget. Execution is less forgiving. The final preserved mixed-format kernel remains 18.33% behind the standard backend in geometric-mean completion throughput. Page-level metadata and launch tuning recover some of the initial loss, but no optimization in the preserved implementation removes the basic cost of a general mixed-format attention loop.

The paper makes three contributions.

1. It develops a page-role model that joins fidelity, physical representation, and logical identity. The model distinguishes a pinned anchor, a raw tail, and a layer-dependent compressed body while leaving the scheduler's block interface intact.
2. It implements direct placement and mixed-format execution in a vLLM-derived server. The implementation includes scale-aware pool allocation, per-page descriptors, INT8 and packed-INT4 storage, and a Triton attention path that combines raw and warm tiles in one streaming softmax.
3. It reports both the benefit and the cost. The study covers capacity across model geometries, the effect of retaining rather than evicting old state, numerical weaknesses in the physical quantizer, and end-to-end throughput across prompt and concurrency regimes.

Two findings shape the rest of the paper. First, compression belongs below a stable logical identity. Once sharing and reclamation enter the picture, a dtype choice is also a lifecycle choice. Second, extra capacity is not itself a speedup. A hierarchy becomes useful only when the server can move pages safely and when each common page mix reaches an execution path narrow enough to compete with a mature homogeneous backend.
